# B2. Blocks, expressions, graph, render

The block model from RUSE carried over to positions. See [graph-format.md](graph-format.md) for the format.

## What it is

- `src/block.rs`: `Block` (`configure`, `control` once per position, `process` adds a term per side, `latency`, `meter`), `ArgInfo` and `BlockInfo`, and `Frame`, one score per side.
- `src/expr.rs`: the expression language, with `ply`, `move`, `phase` and `stm` in place of `rate` and `bpm`.
- `src/spec.rs` and `src/graph.rs`: the JSON description and the runtime. `chain`, `parallel` with gains, `bypass`, `mix`, `only` over the two sides, parameters, modulators. Errors name the path and what exists.
- `src/blocks/`: `material`, `loose`, `king`, `mobility`, `pawns`, each with meters.
- `src/json.rs`: RUSE's JSON reader, so there are still no dependencies.
- `src/pgn.rs`: Lichess PGN in, SAN resolved against the legal moves.
- `src/bin/render.rs`: a game through a graph, one line per ply with every meter; `--json` for a page.
- `tools/loose_fixture.py`: writes the detector's answer for one archive game, for the gate below.

## Gates (`tests/graph_gates.rs`)

- `catalogue_is_described`: docs, ranges, defaults and meters on every block.
- `symmetric`: a position and its mirror score the same for the other side, block by block.
- `loose_matches_the_detector`: the loose block finds the same pieces at the same loss as the Python detector on every ply of the fixture games.
- `repeatable`: two fresh graphs with a random modulator give identical traces.
- `material_is_exact`: known positions to the centipawn.
