# B12. Three lanes, one hook per move

Brian's direction after playing the bot: three loops should run independently, one for the game narration, one for the tutor's move and one for the student's move, and a hook on every move should feed them so that they never collide. He chose the chat layout (three short lines, tagged Game, You and Me, each posted when it is ready) and chose Symbia's own engine to judge his moves.

This increment builds the hooks and the three lanes and moves today's commentary onto them. The lane for the student's move exists but has nothing to say yet; B13 gives it a search and a verdict.

## What is wrong today

One sentence about both moves is built inside the engine, on the clock, after the search ends, and printed just before `bestmove`. The bot reads it after its own move has been sent and posts it from a new thread. Two things follow.

1. The sentence about the student's move needs only the board before that move and the move itself, yet it waits for the end of Symbia's search. It could be said while Symbia is thinking.
2. Each move starts its own posting thread. Two of them can overlap, and a failed chat call drops the rest of that move's lines.

lichess-bot calls the engine class only on Symbia's turn, so `Narrated.play_move` is the one place that sees both moves: its entry carries the student's move and its exit carries Symbia's.

## What changes

**A coach.** The `uci` binary gets a second mode, `uci coach`. It reads one event per line on standard input, runs three lanes on three threads, and writes one line per sentence on standard output. It is the same file, so packaging, install and the update path do not change.

| Event | Sent | Carries |
|---|---|---|
| `student` | at the entry of `play_move` | the ply, the move, the position before it |
| `tutor` | at the exit of `play_move` | the ply, the move, the position before it, the search's depth and score |
| `takeback` | when a takeback is accepted | the first ply that no longer stands |

| Lane | Chat tag | Fed by | Says |
|---|---|---|---|
| Game narration | `Game:` | `student` | what the student's move did (today's `say_theirs`) |
| Student move | `You:` | `student` | nothing yet; B13 |
| Tutor move | `Me:` | `tutor` | what Symbia's move did, who is ahead and how far it looked (today's `say`) |

**Rules that keep the lanes from colliding.**

1. An event holds copies. A lane never touches a live board, and the lanes share no state with each other.
2. Each lane has its own queue and thread. One outbox thread is the only writer, so a line is never cut in two.
3. A line that is more than one ply behind the newest event is dropped, and the coach reports the drop. Chat that trails the board is worse than chat that skips.
4. A takeback voids the lines still waiting for the plies it removes.

**The hook.** `Narrated` starts the coach with the game, sends `student` and `tutor` events, and posts what comes back from one reader thread, in the order the coach prints it. If the coach cannot start, the game goes on without commentary. The engine's own `Narrate` option stays for the other front ends and the fingerprint tool, and is switched off in the bot's config so that the sentence is not built twice.

**The tag counts toward Lichess's 140 characters.** `say` and `say_theirs` take a limit, and the lanes pass 140 minus the tag. Without a tag the limit is the old one, so the engine's own sentences do not change.

**What the chat looks like.** After each exchange: the Game line as soon as the student's move arrives, then the Me line when Symbia has moved. The You line joins in B13, so until then an exchange has two lines. Symbia's first move as White has only a Me line.

## What stays the same

The search, the evaluation, the move and the node counts. The sentences, except for lines that the tag pushes past 140 characters (prediction 1).

## Predictions

Logged on the ledger before any run.

1. **The words do not change.** Over the 602 reference positions at depth 5, the Game line and the Me line the coach writes equal the two halves of the reference sentence with the tag in front. Lines that the tag pushes past 140 characters are refitted by the rule `narrate` already uses. From the B11 reference I count 5 such lines (2 Game, 3 Me), and I predict those 5 and no others differ. About 75 percent sure of the exact count.
2. **The score survives the trip.** Writing a score as UCI text (`cp 12`, `mate 3`, `mate -2`) and reading it back gives the same score for every centipawn value from -999 to 999 and every mate distance, for both sides.
3. **Lines come out whole and in order.** In a stress test with 2,000 events from several producers and lanes that sleep for random milliseconds, every output line is complete, plies never go backward within a lane, and no printed line is more than one ply behind the newest event. About 85 percent sure; the first run of a threaded test often finds an ordering mistake.
4. **A takeback voids the right lines.** After `takeback k`, no waiting line for a ply from k on is printed, and a new event for ply k sent afterward is printed.
5. **The Game line does not wait for the search.** In a test where the tutor lane takes 200 ms per event, the Game line is out within 50 ms of its event in all of 100 events.
6. **It loads and speaks.** The offline smoke test through lichess-bot's mock site passes: the class starts the coach, the chat gets one Game line per student move and one Me line per engine move, each tagged and at most 140 characters, with no "Could not post" warning, and the coach ends with the game.
7. **Nothing for the search to pay.** The engine path is untouched: the reference fingerprint with `Narrate` on is still `783e378f…974f` over 106,989,330 nodes. An idle coach uses under 0.05 s of CPU in 30 s.
8. **The Linux build agrees.** The musl build writes the same coach lines for the same events as the Mac build, over all 602 positions.
9. **It reads right in a game.** After a push and a game, Brian sees the Game line before Symbia's move and the Me line after it, with no line out of order. This needs his yes for the firewall step and a game.

Other gates. The Rust suite passes with 11 new tests (2 for the score round trip, 9 for the coach; 54 in the library in all), and the coach tests passed 10 runs in a row. `cargo fmt` and `clippy` are clean, the browser (wasm) build still compiles with the coach left out of it, and `tools/package.sh` builds the Linux package from the musl engine (release `beb8274b353f`).

Found along the way, and logged: the hook's stale rule stops at the pipe, so a slow chat call still delivers old lines late; the takeback message from the hook has no offline test, because the mock site plays only Scholar's mate; Lichess's chat rate limit is unknown, and a bullet game now sends two lines an exchange.

## Not in this increment

- The student lane's search and verdicts (B13). It will need a search that does not touch the clock, a short list of the best replies kept while the student thinks, and a rule for what to say about a move that was fine.
- Game-level narration beyond the student's move: the opening, the phase of the game, the clocks.
- The spectator room. All lines go to the player chat.
- More than one game at a time. Each game process owns its own coach.
